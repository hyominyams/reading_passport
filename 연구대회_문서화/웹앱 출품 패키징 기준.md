# 웹앱 출품 패키징 기준

- 작성일: 2026-04-27
- 기준 문서: `2026. 디지털교육 연구대회(전남 예선) 추진 계획 - 제20회 디지털교육 연구대회(전국 본선)`
- 목적: World Docent 웹애플리케이션을 교육용SW·AI분과에 제출할 때 필요한 소프트웨어 제출 기준을 정리한다.

## 1. 교육용SW·AI분과 제출물

교육용SW·AI분과는 다음 자료를 제출한다.

- 출품원서 인쇄본 1부
- 출품서약서 인쇄본 1부
- 소프트웨어 파일 일체
  - 출품작 소프트웨어
  - 제작에 사용된 원본 폴더 전체의 소스파일
  - 멀티미디어 요소자료
  - 실행 가능한 배포 파일
  - 시도명, 학교명, 직위, 출품자명이 표시되지 않도록 처리
- 연구보고서
  - 인쇄본 흑백 6부
  - 파일 4종: HWP, PDF, 블라인드 HWP, 블라인드 PDF
  - 본문 10쪽 이내
  - 요약서 2쪽 이내
  - 참고자료 10쪽 이내
  - 총 22쪽 이내
- 개인정보 수집·이용 동의 확인서 인쇄본 1부
- 해당 시 기타 파일
  - 최근 2년간 디지털교육 관련 연구학교 재직 이력이 있으면 결과보고서와 계획서 제출

## 2. 연구보고서에 반드시 포함할 웹앱 정보

교육용SW·AI분과 보고서에는 다음 내용을 반드시 포함한다.

- 소프트웨어 개발 환경
  - 개발 언어
  - 개발 프로그램
  - 프레임워크와 주요 라이브러리
- 최적 해상도 및 최적화 기기
  - OS 버전 표기
- 소프트웨어 사용을 위한 최소 사양
- 소프트웨어 사용 안내 절차 및 도구 설명
- 특정 도구 또는 기능 접근 여부
  - GPS, 카메라, 녹음기 등
  - 접근권한이 필요한 경우 고지 의무 준수
- 웹 애플리케이션 운영에 필요한 서버 환경
  - 예: Node.js, Supabase, Vercel, PostgreSQL, OpenAI API 등
- 도표, 멀티미디어 자료 등의 사용권 확보 증빙서류
- 개발한 소프트웨어의 수업 적용 및 활용 결과

World Docent에 맞춘 기재 예:

- 개발 환경: Next.js App Router, React, TypeScript, Tailwind CSS, Supabase, Vercel, OpenAI API
- 운영 환경: 최신 Chrome, Edge, Safari / Windows, macOS, Linux
- 서버 환경: Node.js 기반 Next.js 서버, Supabase PostgreSQL/Auth/Storage, Vercel 배포 환경
- AI 환경: 서버 API를 통한 생성형 AI 호출, 학생 외부 AI 서비스 직접 접속 없음
- 최적 해상도: 1920x1080 이상
- 학생용 권장 기기: 노트북, 데스크톱, 태블릿 브라우저

## 3. 제출용 USB 폴더 구조

계획서의 권고 구조는 다음과 같다.

```text
USB/
  document/
  media/
    image/
    movie/
    sound/
  program/
  source/
```

### 3.1 document 폴더

필수 제출서류를 저장한다.

넣을 자료:

- 연구보고서 HWP
- 연구보고서 PDF
- 블라인드 연구보고서 HWP
- 블라인드 연구보고서 PDF
- 주요 화면 캡처 이미지
  - 파일명 예: `WorldDocent-01.jpg`
  - jpg 또는 png
  - 해상도 1024x768 이상
- 실행 매뉴얼
- 데모 계정 안내
- 서버 환경 설명서
- 청소년 보호정책 캡처
- AI 활용 관리표
- 저작권 증빙자료 목록

### 3.2 media 폴더

소프트웨어에 사용되는 멀티미디어 교육자료를 저장한다.

권장 구조:

```text
media/
  image/
  movie/
  sound/
  fonts/
  licenses/
```

주의:

- 계획서 기본 구조에는 fonts 폴더가 없지만, 폰트는 저작권 점검 대상이므로 별도 정리하는 것이 좋다.
- 본인이 개발하지 않은 모든 외부 자료는 출처와 사용권을 기록한다.
- 소프트웨어 화면에서도 출처가 확인될 수 있어야 한다.

### 3.3 program 폴더

실행 가능한 프로그램 파일을 저장한다.

계획서 기준:

- 웹애플리케이션의 경우 시작 파일 이름으로 `index.html`을 사용한다.
- 즉시 실행 가능한 형태의 프로그램 폴더 구조를 개발한 그대로 저장한다.

해석:

이 문구를 "모든 웹앱을 정적 HTML 파일 하나로 변환하라"는 뜻으로 보면 안 된다. 특히 Next.js, Supabase, Vercel, OpenAI API처럼 서버와 데이터베이스가 필요한 웹앱은 `index.html` 하나만으로 전체 기능을 실행할 수 없다.

계획서가 요구하는 `index.html`은 심사위원이 USB를 열었을 때 웹앱을 시작할 수 있는 진입 파일로 해석하는 것이 현실적이다. 즉, 서버형 웹앱의 경우 `program/index.html`은 다음 역할을 한다.

- 배포된 웹앱 접속 버튼 제공
- 데모 계정 안내
- 권장 브라우저 및 해상도 안내
- 서버 환경 안내
- 인터넷 연결 필요 여부 안내
- 로컬 실행을 원하는 경우 `source` 폴더와 실행 매뉴얼 위치 안내

World Docent 적용 방식:

World Docent는 Vercel, Supabase, OpenAI API가 필요한 서버 기반 웹앱이므로 USB 안의 정적 `index.html`만으로 전체 기능을 완전히 실행하기 어렵다. 따라서 `program/index.html`은 심사용 실행 안내 런처 역할로 구성하는 것이 현실적이다.

`program/index.html`에 포함할 내용:

- 서비스명
- 연구보고서 제목
- 대상 학년
- 배포 URL
- 데모 계정
- 관리자/교사/학생 계정별 접속 방법
- 브라우저 권장 환경
- 서버 기반 기능 안내
- 인터넷 연결 필요 안내
- AI API 키는 제출 파일에 포함하지 않는다는 안내

가능하면 다음도 준비한다.

- 오프라인 시연용 주요 화면 캡처
- 수업 흐름 영상 또는 GIF
- 네트워크 장애 시 설명용 PDF

가장 안전한 제출 방식:

1. `program/index.html`: 배포 URL로 접속하는 심사용 런처
2. `source/`: 실제 소스 코드 전체
3. `document/실행매뉴얼.pdf`: 로컬 실행 방법과 서버 환경 설명
4. `document/서버환경_설명서.pdf`: Vercel, Supabase, OpenAI API 구조 설명
5. `document/주요화면/`: 네트워크 장애 대비 화면 캡처
6. 발표심사: 실제 배포 서버와 데모 계정으로 시연

기관 확인이 필요한 지점:

- `program/index.html`이 배포 URL 접속용 런처여도 되는지
- 클라우드 서버 기반 웹앱의 경우 제출 시점부터 심사 종료까지 배포 서버를 유지하면 되는지
- API 키와 DB 접속 정보는 보안상 제출하지 않고 `.env.example`과 서버 환경 설명으로 대체해도 되는지
- 인터넷 연결이 필요한 웹앱으로 심사 진행이 가능한지

### 3.4 source 폴더

제작된 소스 폴더 전체를 저장한다.

넣을 자료:

- 프로젝트 소스 코드 전체
- `package.json`
- `package-lock.json` 또는 잠금 파일
- `README` 또는 실행 안내
- `.env.example`
- Supabase migration 파일
- seed 데이터 또는 데모 데이터 생성 스크립트
- 라이선스/출처 관련 문서

주의:

- 실제 `.env` 파일, API 키, Supabase service role key는 절대 포함하지 않는다.
- 소스 코드와 실행 가능한 배포 파일이 불일치하면 등외 처리 사유가 될 수 있다.
- 제출용 소스와 실제 배포 서버의 버전을 맞춘다.

## 4. 웹애플리케이션 최소 기준

계획서의 웹애플리케이션 최소 기준:

- 최신 버전의 범용 웹브라우저에서 정상 동작
  - Edge
  - Chrome
  - Safari 등
- 모든 PC용 운영체제에서 가능
  - Windows
  - Linux
  - macOS
- 화면해상도 1920x1080 픽셀 이상

World Docent 점검 항목:

- Chrome 1920x1080
- Edge 1920x1080
- Safari 1920x1080
- macOS에서 정상 동작
- Windows 환경 가능 여부 확인
- 모바일/태블릿 반응형은 가산적 장점이지만, 최소 기준은 PC 브라우저 1920x1080이다.

## 5. 소프트웨어 심사 관련 주의사항

계획서상 소프트웨어 심사는 USB로 제출한 파일을 실행하여 진행한다. 발표심사 시에는 제작된 툴이 담긴 노트북이나 앱 실행 가능 기기를 미러링하여 심사할 수 있다.

등외 처리 주의사항:

- 제출 프로그램의 오류로 심사를 실시할 수 없는 경우
- 실행 가능한 소프트웨어 또는 소스 코드를 제출하지 않은 경우
- 실행 가능한 소프트웨어와 소스 코드가 일치하지 않은 경우

World Docent 대응:

- 심사용 배포 URL을 안정적으로 유지한다.
- 제출 당일 데모 계정이 정상 로그인되는지 확인한다.
- Supabase DB와 Storage가 정상인지 확인한다.
- OpenAI API 호출이 필요한 기능은 쿼터와 결제 상태를 확인한다.
- API 실패 시에도 전체 시연이 멈추지 않도록 오류 메시지를 정리한다.
- 핵심 흐름은 사전 생성된 데모 데이터로도 보여줄 수 있게 한다.

## 6. 블라인드 처리

계획서상 소프트웨어 화면 및 파일명에는 시도명, 학교명, 직위, 출품자명이 표시되지 않아야 한다.

점검할 것:

- 앱 시작 화면
- footer
- 교사 대시보드
- 관리자 대시보드
- 데모 계정 이름
- 클래스명
- 학생 이름
- 서재 작품 작성자명
- 파일명
- 스크린샷
- 연구보고서 블라인드본

주의:

- `청소년 보호 담당관: 박준효`는 정책 페이지에는 필요하지만, 심사용 블라인드 소프트웨어 화면에서 출품자명으로 해석될 수 있는지 확인이 필요하다.
- 블라인드 제출본에서는 담당관 실명을 유지할지, `청소년 보호 담당관`과 이메일만 둘지 담당 기관 확인이 필요하다.

## 7. 저작권 및 출처 표시

계획서 기준:

- 출품작 내 타인 제작 자료를 사용하면 원저작자의 승인을 받은 사용권 확보 증빙 자료를 참고자료에 첨부해야 한다.
- 소프트웨어 화면에도 출처를 기재해야 한다.
- 자료 목록에 없는 멀티미디어 파일은 저작권 위반으로 등외 처리될 수 있다.
- 본인 제작이 아닌 모든 외부 인용자료가 출처 기재 대상이다.
- 폰트도 사용 범위와 무료 사용 여부를 확인해야 한다.

World Docent 대응:

- 그림책 공동창작 동의서 준비
- Hidden Stories 자료별 출처 표시
- Unsplash 등 외부 이미지 사용 시 출처 및 라이선스 정리
- 폰트 라이선스 정리
- AI 생성 이미지의 생성 경위와 이용 범위 정리
- `멀티미디어 교육자료 목록` 작성
