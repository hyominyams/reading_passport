# AI SW교육용 스마트앱 연구대회 보완 기록

- 작성일: 2026-04-27
- 프로젝트: World Docent / reading_passport
- 목적: 제20회 디지털교육연구대회 교육용SW·AI분과 출품 준비를 위해, 현재 웹앱의 가치와 보완점을 AI와 사람이 함께 이어서 작업할 수 있도록 정리한다.

## 1. 현재 결론

현재 프로젝트는 연구대회 출품 가치가 높다. 단, 지금 상태 그대로 출품하면 앱 구현의 강점은 드러나지만, 연구대회 평가에서 중요한 "수업 적용 근거", "효과 검증", "일반화 가능성", "저작권·개인정보·생성형 AI 관리"가 부족할 수 있다.

핵심 판단은 다음과 같다.

- 웹앱의 기술 구현 범위는 기존 입상작들과 비교해도 넓고 깊다.
- 독서교육, 세계시민교육, AI 기반 창작, 질문 생성, 교사용 관리 기능이 하나의 수업 흐름으로 연결되어 있어 출품 주제로 충분하다.
- 다만 연구대회는 "잘 만든 앱"만 평가하지 않고, 앱이 실제 수업을 어떻게 개선했는지, 학생 역량이 어떻게 변했는지, 다른 교사가 쓸 수 있는지까지 본다.
- 따라서 앞으로의 작업은 기능을 더 늘리는 것보다 "출품 가능한 연구 형태로 좁히고 증거를 만드는 일"이 우선이다.

## 2. 추천 출품 방향

가장 적합한 분과는 교육용SW·AI분과다.

추천 연구 제목 후보:

1. AI 글로벌 독서여권 앱을 활용한 초등학생 질문 생성 및 문화다양성 감수성 신장 연구
2. 그림책으로 읽고 묻고 창작하는 AI 글로벌 독서여권 앱 개발 및 적용
3. AI 기반 글로벌 그림책 독서여권 앱을 통한 질문 생성 역량과 세계시민 감수성 함양

현재 앱의 모든 기능을 다 강조하기보다, 아래 4단계 수업 흐름을 중심으로 좁히는 것이 좋다.

1. Story Read: 그림책 읽기, 감정 선택, 한 줄 감상
2. Hidden Stories: 책 너머의 문화·사회·환경 배경 탐색
3. Expanding World: 학생 질문 생성, 질문 보드, 사고 확장
4. My World: AI 도움을 받은 나만의 이야기 창작과 공유

핵심 연구 주제는 "AI가 글을 대신 써주는 앱"이 아니라, "학생이 더 잘 읽고, 더 좋은 질문을 만들고, 자신의 세계로 재구성하도록 돕는 독서교육 도구"로 잡아야 한다.

교육용SW·AI분과 심사 기준:

- 연구 목적: 30점
  - 학생 역량 향상에 적합한 교수·학습 주제인가
  - 기존 입상작 및 시판 소프트웨어와 차별화되는가
  - 소프트웨어 개발에 적합한 교육내용과 학습주제인가
  - 학습내용이 체계적으로 구성되고 교육과정과 연계되는가
- 구현 기술: 20점
  - 오류 없이 안정적으로 구동되는가
  - 사용자 입력에 대한 반응 속도가 적절한가
  - 학습동기를 유발하는 기능이 구현되어 있는가
  - 학습목표 달성 및 평가에 효율적인 교사-학생-콘텐츠 인터페이스인가
- 수업 활용: 20점
  - 소프트웨어를 활용한 수업 적용과 연구 과정이 구체적인가
  - 실제 수업 적용 과정이 제시되어 있는가
  - 수업 진행 절차에 맞게 자료 제시, 교수·학습 전략이 구현되어 있는가
  - 교실 수업에 적합한 인터페이스인가
- 일반화 가능성 및 시사성: 30점
  - 다른 학교와 교사가 적용할 수 있는가
  - 지속적으로 발전 가능한가
  - 연구 활동 과정과 결과에서 구체적 시사점을 도출했는가
  - 기존 입상작 및 시판 소프트웨어와 결론·제언이 차별화되는가

중요한 운영상 유의점:

- 제출 서류 미비, 연구 주제와 교수·학습 개선 관련성 부족, 원자료 미보관은 등외 처리 사유가 될 수 있다.
- 설문조사 답변지 등 Raw Data는 심사 결과 발표일까지 보관해야 하며, 입상자는 입상 후 최소 1년 이상 보관해야 한다.
- 연구보고서와 소프트웨어에는 블라인드 처리가 필요하다. 학교명, 교사명, 출품자 정보가 소프트웨어 화면에 노출되지 않도록 해야 한다.
- 기존 발표작, 상용 소프트웨어, 타인의 소프트웨어 화면을 단순 재구성한 작품은 표절 심사 대상이 될 수 있다.
- 웹애플리케이션은 최신 범용 브라우저에서 정상 동작하고, Windows, macOS, Linux 등 PC 운영체제에서 접근 가능해야 하며, 1920x1080 해상도를 기준으로 점검해야 한다.

## 4. 기존 입상작에서 확인한 성공 패턴

검토한 자료:

- 내 이름은 검색왕
- AI 디지로그 밸런스 프로그램으로 배움과 마음의 균형 찾기
- AI 기반 자기주도적 맞춤법 코스웨어 "대왕님의 맞춤법 상담소"
- 함께하는 니듀테크 기반 환경 문제해결 실천학습
- 디지털 월드 어드벤처

입상작들의 공통점:

- 연구 문제가 명확하다.
  - 예: 검색 신뢰도 판단, 맞춤법 자기주도 학습, 디지털 시민성, 수학 역량과 사회정서역량 등
- 적용 대상과 기간이 분명하다.
  - 예: 3학년 21명, 4학년 19명, 1~6학년 60명 등
- 사전-사후 검사가 있다.
  - 단순 만족도만이 아니라 역량 변화, 학업 성취도, 태도 변화를 수치로 제시한다.
- 기능 설명보다 수업 적용 장면을 많이 보여준다.
  - 차시별 활동, 학생 산출물, 교사 관찰, 인터뷰, 로그 분석이 들어간다.
- 결과가 통계 또는 루브릭으로 정리된다.
  - t-test, Wilcoxon, 평균 변화, 루브릭 점수, 교사 만족도 등을 사용한다.
- 일반화 가능성을 제시한다.
  - 다른 학년, 다른 단원, 다른 교사가 어떻게 쓸 수 있는지 보여준다.

World Docent가 배워야 할 점:

- 앱 기능을 많이 설명하는 것보다, 앱이 학생의 질문·독해·문화이해·창작에 어떤 변화를 만들었는지 증명해야 한다.
- "AI가 있어서 새롭다"가 아니라 "AI가 교실 수업의 어떤 병목을 해결했는가"를 보여줘야 한다.
- 수업 전후 결과가 없으면 구현 기술이 좋아도 연구대회 점수는 제한될 수 있다.

## 6. 현재 부족한 점

### 6.1 연구 문제가 넓다

현재 앱은 독서, 세계시민교육, 문화다양성, 질문 생성, AI 창작, 그림책 제작, 서재, 교사 관리까지 모두 다룬다. 그대로 보고서에 쓰면 연구 초점이 흐려질 수 있다.

보완 방향:

- 핵심 종속변인을 2~3개로 제한한다.
- 추천 종속변인:
  - 질문 생성 역량
  - 문화다양성 감수성 또는 세계시민 감수성
  - AI 활용 창작 자기효능감
  - 독서 흥미 또는 독서 몰입
- 연구 제목과 보고서 전체가 이 변인들을 중심으로 움직이게 한다.

### 6.2 실제 수업 적용 데이터가 부족하다

현재 앱 구현은 되어 있지만, 연구대회용으로 필요한 사전-사후 데이터, 활동 로그, 학생 산출물 분석, 인터뷰 자료가 아직 부족하다.

필요한 자료:

- 사전 설문
- 사후 설문
- 질문 생성 루브릭 평가
- 이야기 산출물 루브릭 평가
- 학생 활동 로그
- 학생 작품 예시
- 교사 관찰 기록
- 학생 소감
- 동료교사 또는 전문가 피드백
- 수업 장면 사진 또는 캡처

### 6.3 교육과정 연결이 더 명확해야 한다

현재 프로젝트의 교육적 의도는 분명하지만, 보고서에서는 교육과정 성취기준과 연결되어야 한다.

연결 가능한 영역:

- 국어: 읽기, 질문 만들기, 감상 표현, 쓰기, 매체 활용
- 사회: 세계 여러 나라, 문화 이해, 지구촌 문제
- 도덕: 타인 존중, 공감, 책임, 디지털 윤리
- 창의적 체험활동: 독서교육, 세계시민교육, 디지털 시민성
- 정보/AI 소양: 생성형 AI의 올바른 활용, AI 산출물 검토, 디지털 자료 평가

보완 방향:

- 출품 보고서에 차시별 성취기준 매핑표를 넣는다.
- 앱 기능별로 어떤 성취기준을 지원하는지 표로 정리한다.

### 6.4 저작권·AI 약관·개인정보 대응 자료가 부족하다

그림책은 사용자와 동료가 직접 만든 것이라 가장 큰 저작권 리스크는 줄었다. 하지만 출품을 위해서는 증빙이 필요하다.

남아 있는 리스크:

- 공동저작물 이용 동의
- 그림책 안에 사용된 폰트, 이미지, 질감, 참고자료의 권리
- Hidden Stories 외부 자료의 출처와 라이선스
- AI 생성 이미지의 이용 범위
- 학생 작품 공개 동의
- 학생 이름, 얼굴, 학급 정보 등 개인정보 노출
- 생성형 AI 서비스 약관상 연령 제한 및 보호자/학교 동의
- AI 프롬프트와 로그에 개인정보가 들어가는 문제

### 6.5 출품용 안정성 검증 자료가 부족하다

교육용SW·AI분과는 실제 실행 가능한 소프트웨어와 소스 코드가 중요하다. 웹앱의 경우 서버 환경, 실행 방법, 계정, API 키 관리, 데모 데이터가 명확해야 한다.

필요한 자료:

- 실행 매뉴얼
- 관리자/교사/학생 테스트 계정
- 서버 환경 설명
- `.env` 예시
- Supabase 테이블 구조
- AI API 키 미포함 안내
- 데모 데이터 복원 방법
- 최신 브라우저 동작 확인
- 1920x1080 화면 점검
- 모바일/태블릿 대응 점검
- 장애 상황 대응 설명

## 7. 저작권 리스크 정리

### 7.1 그림책

현재 확인된 사실:

- 그림책은 사용자와 동료가 직접 제작했다.
- 따라서 외부 출판 그림책 PDF를 무단 탑재하는 위험은 낮다.

그래도 필요한 증빙:

- 공동저작물 이용 동의서
- 대회 제출, 수업 활용, 웹앱 탑재, 교육 목적 공개에 대한 동의
- 원본 파일과 제작 과정 증빙
- 폰트 사용 가능 범위 확인
- 삽화 제작에 외부 사진, AI 이미지, 상용 소재가 들어갔는지 확인

보고서에 쓸 수 있는 표현:

> 본 연구에 활용한 그림책 원문과 삽화는 연구자와 동료 교사가 공동 창작한 자료이며, 대회 제출 및 수업 적용, 웹앱 탑재, 교육 목적 공개 범위에 대한 공동저작자 동의를 확보하였다.

### 7.2 Hidden Stories 자료

Hidden Stories는 저작권 리스크가 가장 클 수 있다.

주의할 자료:

- YouTube 영상
- 외부 PDF
- 웹 이미지
- 뉴스 기사
- 지도
- 국가 사진
- 배경음악
- 아이콘
- 폰트

보완 방식:

- 링크만 제공하는 자료와 앱 내부 저장 자료를 구분한다.
- 앱 내부에 저장하는 자료는 사용권이 확실한 것만 넣는다.
- 모든 자료에 출처 URL, 저작권자, 라이선스, 온라인 탑재 가능 여부를 기록한다.
- 심사위원이 확인할 수 있는 URL을 자료 목록에 남긴다.
- 가능하면 직접 제작 자료, 공공누리, Wikimedia Commons, Unsplash 등 라이선스가 명확한 자료 위주로 구성한다.
- 단, Wikimedia Commons는 파일마다 라이선스가 다르므로 개별 확인이 필요하다.

### 7.3 폰트

폰트는 자주 놓치는 리스크다.

확인할 것:

- 앱 UI 폰트
- 그림책 PDF 안의 폰트
- 연구보고서 폰트
- 발표자료 폰트
- 생성 PDF에 포함되는 폰트

보완 방식:

- 상업적 이용 및 배포 가능 폰트를 사용한다.
- 폰트 라이선스 URL과 사용 범위를 기록한다.
- 불확실한 폰트는 제거하고 시스템 기본 폰트 또는 명확한 공개 폰트로 교체한다.

## 8. 생성형 AI 리스크 정리

제20회 운영계획에는 ChatGPT, Gemini 등 생성형 AI 활용 수업 사례가 포함될 경우 해당 서비스 약관상 의무, 연령 제한 등을 준수해야 한다는 취지가 들어 있다.

현재 앱의 AI 사용 지점:

- 책 분석
- 질문 생성 및 검증
- AI 가이드 채팅
- 이야기 초안 생성
- 번역
- 이미지 생성
- 장면 생성
- 캐릭터 생성

보완 원칙:

- 학생이 직접 외부 AI 서비스 계정을 만들지 않게 한다.
- API는 교사/학교/연구자 관리 계정으로 서버에서 호출한다.
- 학생 개인정보를 프롬프트에 넣지 않는다.
- 이름, 학교, 학급, 얼굴, 연락처, 주소 등은 AI 입력에서 제외한다.
- AI 출력은 최종 산출물이 아니라 초안, 피드백, 보조자료로 위치시킨다.
- 학생이 AI 결과를 검토하고 수정하는 절차를 수업 안에 넣는다.
- 부적절 내용 필터링과 교사 확인 절차를 문서화한다.
- AI 생성 이미지가 특정 작가, 유명 캐릭터, 실제 인물, 저작권 보호 캐릭터를 모방하지 않도록 한다.

보고서에 넣을 AI 활용 관리표 항목:

- 기능명
- 사용 모델 또는 서비스
- 입력 데이터
- 출력 데이터
- 학생 개인정보 포함 여부
- 교사 검토 여부
- 학생 수정 여부
- 위험 요인
- 대응 방안

예시:

| 기능 | AI 활용 | 입력 | 출력 | 위험 | 대응 |
| --- | --- | --- | --- | --- | --- |
| 질문 피드백 | 학생 질문에 대한 사고 확장 피드백 | 질문 텍스트, 책 정보 | 피드백 문장 | 개인정보 입력 가능성 | 이름·학교 정보 입력 금지, 저장 전 필터링 |
| 이야기 초안 | 학생 아이디어를 이야기 구조로 정리 | 학생 아이디어, 선택 유형 | 초안 | AI 대필 우려 | 학생 수정 단계 필수, 최종본에 수정 기록 반영 |
| 이미지 생성 | 학생의 장면 설명을 이미지로 생성 | 장면 설명, 캐릭터 설명 | 장면 이미지 | 저작권 캐릭터 모방 | 유명 IP·작가명 입력 금지, 교사 검토 |

## 9. 개인정보 및 학생 산출물 리스크

현재 앱은 학생 활동 로그, 질문, 이야기, 이미지, 서재 작품을 저장한다. 연구대회 보고서와 앱 시연에서 개인정보 노출이 생기지 않게 해야 한다.

학생 산출물 저작권 원칙:

- 학생이 직접 작성, 수정, 선택, 편집, 구성한 질문, 감상, 이야기, 그림책, 장면 구성 등 학생 산출물의 저작권은 학생에게 귀속된다.
- 앱 운영자, 교사, 학교, 연구자는 학생 산출물의 저작권을 양도받지 않는다.
- 앱 운영자는 게시 동의와 교육 목적 이용허락을 받은 범위 안에서만 학생 산출물을 저장, 게시, 전시, 연구보고서와 대회 자료에 활용한다.
- 학생 산출물은 상업적 이용을 하지 않는다는 원칙을 약관과 동의서에 명시한다.
- AI API 비용을 운영자나 교사가 부담하더라도, 그 비용 부담은 학생 창작물의 저작권을 운영자에게 이전시키는 근거가 되지 않는다.
- AI가 생성한 초안, 문장, 이미지는 학생의 학습과 창작을 보조하는 자료로 취급하고, 최종 산출물은 학생의 선택, 수정, 편집, 검토 과정을 거치도록 한다.

약관 또는 동의서 권장 문구:

> 학생이 본 서비스에서 작성, 수정, 편집, 구성한 질문, 감상, 이야기, 그림책, 이미지 구성 등 산출물의 저작권은 해당 학생에게 귀속됩니다. 운영자와 교사는 학생 산출물의 저작권을 양도받지 않습니다.
>
> 학생 산출물은 수업 운영, 학급 내 공유, 학습 결과 확인, 연구보고서 작성, 디지털교육연구대회 제출 및 발표 등 교육활동의 목적으로만 사용됩니다. 이 범위 안에서 운영자는 학생 산출물을 저장, 복제, 전송, 전시, 게재할 수 있으며, 학생과 법정대리인은 이에 대해 비독점적으로 이용을 허락할 수 있습니다.
>
> 운영자는 학생 산출물을 광고, 판매, 유료 콘텐츠, 출판, 상품 제작, 제3자 영리 제공 등 상업적 목적으로 이용하지 않습니다.
>
> 학생 산출물을 바탕으로 2차적저작물을 작성하거나, 별도의 출판물로 발간하거나, 대회 심사 범위를 넘어 공개 전시, 외부 플랫폼 게시, 공공 배포를 진행해야 하는 경우에는 사전에 원저작자인 학생 및 법정대리인에게 별도 동의를 구한 뒤 진행합니다.
>
> AI 기능 이용에 필요한 비용은 운영자가 부담할 수 있으나, 비용 부담은 학생 산출물에 대한 저작권 이전을 의미하지 않습니다. AI 산출물은 학생의 학습과 창작을 돕는 보조 자료이며, 학생은 최종 산출물을 직접 검토하고 수정합니다.
>
> 학생 또는 법정대리인은 공개 게시 동의를 철회할 수 있으며, 철회 이후 운영자는 합리적인 기간 내 공개 게시를 중단합니다. 단, 철회 이전에 이미 제출된 연구대회 심사자료, 비식별 통계, 수업 기록 등은 관련 법령과 대회 운영 기준에 따라 보관될 수 있습니다.

필요한 조치:

- 학생 계정은 실명 대신 번호 또는 별칭 사용
- 보고서와 발표자료에는 학생 이름, 학교명, 얼굴, 학급 정보 비식별 처리
- 학생 작품 공개는 동의 받은 경우만 허용
- 서재 공개 기본값은 비공개 또는 학급 공개로 설정하는 것이 안전
- 공개 작품에는 교사 승인 절차를 두는 것이 좋다
- 활동 로그와 설문 원자료는 연구 종료 후 보관 기간과 삭제 절차를 정한다

동의서에 포함할 항목:

- 에듀테크 활용 수업 참여
- 학생 활동 기록 수집
- 학생 작품 연구보고서 활용
- 학생 작품 웹앱 내 공개 여부
- 사진 또는 화면 캡처 활용 여부
- 개인정보 보관 기간
- 동의 철회 가능성

## 10. 현재 앱에서 보완하면 좋은 기능

출품 전에 기능을 무리하게 늘리기보다, 심사 리스크를 줄이는 기능을 우선한다.

우선순위 높음:

- 자료별 출처/라이선스 입력 필드
  - books, hidden_content, generated assets에 source_url, license, permission_note, creator 필드 추가 고려
- 학생 작품 공개 기본값 변경
  - public 기본값보다 secret 또는 class 기본값이 안전
- AI 활용 고지
  - 로그인 또는 활동 시작 전 간단한 AI 활용 안내
- 교사 승인 기반 공개
  - 학생 작품이 공개 서재에 올라가기 전에 교사 승인
- 저작권/AI 필터링 체크리스트
  - 교사가 Hidden Stories를 등록할 때 출처와 사용권 확인 체크
- 블라인드 모드
  - 출품 시 소프트웨어 화면에서 학교명, 교사명, 출품자명 제거
- 데모 모드
  - 심사용 계정과 데모 데이터로 안정 실행 가능하게 구성

우선순위 중간:

- 활동 로그 다운로드
- 사전-사후 설문 결과 CSV 다운로드
- 질문 루브릭 평가 기능
- 이야기 루브릭 평가 기능
- 학생별 도장/활동률/작품 수 자동 통계
- 교사용 연구자료 출력 기능

## 11. 추천 연구 설계

대상:

- 초등 5~6학년 권장
- 한 학급 또는 두 학급
- 최소 4주 이상, 가능하면 6~8주

운영 방식:

- 1차시: 사전 설문, 앱 소개, 그림책 배경 이해
- 2차시: Story Read, 감정 선택, 한 줄 감상
- 3차시: Hidden Stories 탐색, 문화·사회 배경 이해
- 4차시: Expanding World 질문 만들기, 질문 보드 공유
- 5차시: 좋은 질문 고르기, AI 피드백으로 질문 개선
- 6차시: My World 이야기 구상, AI 가이드 채팅
- 7차시: 이야기 초안 수정, 장면 구성
- 8차시: 그림책 완성, 서재 공유, 사후 설문

측정 도구:

- 질문 생성 역량 루브릭
  - 사실 확인 질문
  - 이유·관계 질문
  - 관점 전환 질문
  - 문화·사회 배경 질문
  - 실천·확장 질문
- 문화다양성 감수성 설문
  - 다른 문화에 대한 관심
  - 고정관념 점검
  - 공감
  - 차이 존중
  - 세계 문제와 나의 연결성
- AI 활용 창작 자기효능감 설문
  - AI 도움을 이해하고 활용할 수 있음
  - AI 결과를 비판적으로 검토할 수 있음
  - AI 초안을 내 생각으로 수정할 수 있음
  - AI와 함께 창작하는 과정에 자신감이 있음
- 독서 흥미 또는 독서 몰입 설문
  - 그림책 읽기 흥미
  - 질문 만들기 흥미
  - 배경 탐색 흥미
  - 나만의 이야기 쓰기 흥미

앱 로그 지표:

- 로그인 횟수
- 책 열람 완료 여부
- 도장 획득 수
- Hidden Stories 열람 수
- 질문 작성 수
- AI 피드백 후 질문 수정 여부
- 이야기 초안 생성 여부
- 학생 수정량
- 장면 생성 수
- 최종 작품 완성 여부
- 서재 등록 여부

분석 방법:

- 사전-사후 평균 비교
- 표본 수가 작으면 Wilcoxon signed-rank test 사용 가능
- 정규성 검정 후 t-test 또는 Wilcoxon 선택
- 질문/이야기 산출물은 루브릭으로 2인 이상 평가하면 신뢰도 확보에 유리
- 학생 소감과 교사 관찰은 질적 자료로 보완

### 16.2 ChatGPT, Gemini 직접 사용 여부에 대한 판단

계획서의 주의사항은 "연구보고서 내용에 Chat GPT, Gemini 등 생성형 AI 활용 수업 사례가 포함될 경우 해당 서비스 약관상 의무(연령 제한 등) 준수"를 요구한다. 동시에 교육용SW·AI분과 연구 내용에는 "AI 요소가 반드시 포함되어야 하는 것은 아님"이라고 되어 있다.

현재 World Docent는 학생이 ChatGPT 또는 Gemini 웹사이트에 직접 접속하거나 개인 계정을 만들어 사용하는 구조가 아니다. 이 점은 리스크를 낮춘다.

다만 앱 내부에서 OpenAI API 기반으로 질문 피드백, 이야기 초안, 번역, 이미지 생성 등을 제공한다면, 연구보고서상으로는 "생성형 AI 활용 수업 사례"에 해당할 수 있다. 따라서 "직접 ChatGPT/Gemini를 사용하지 않으므로 아무 설명이 필요 없다"가 아니라, 다음과 같이 설명하는 것이 안전하다.

권장 설명:

> 본 연구에서 학생은 ChatGPT, Gemini 등 외부 생성형 AI 서비스에 직접 가입하거나 접속하지 않는다. 생성형 AI 기능은 교사와 운영자가 관리하는 서버 기반 교육용 웹앱 내부 기능으로 제공되며, 학생 개인정보를 프롬프트에 포함하지 않고, AI 산출물은 학생의 질문 개선과 창작 활동을 돕는 보조자료로만 활용한다. 학생은 AI 산출물을 그대로 제출하지 않고 검토, 수정, 재구성하는 과정을 거친다.

보완해야 할 약관 대응:

- 학생이 외부 AI 서비스 계정을 생성하지 않는다는 점을 명확히 쓴다.
- AI API 호출은 운영자 관리 계정과 서버에서 처리한다고 쓴다.
- 학생 개인정보를 AI 입력값에 넣지 않는다고 쓴다.
- AI 산출물은 최종 산출물이 아니라 초안, 피드백, 보조자료라고 쓴다.
- 교사 검토와 학생 수정 절차가 있다는 점을 쓴다.
- 보호자 동의서에는 "AI 기반 학습 보조 기능을 활용할 수 있음"을 명시한다.

- 학생 산출물은 교육활동 목적으로만 사용한다.
- 상업적 이용은 하지 않는다.
- 2차적저작물 작성, 별도 출판, 공개 전시, 외부 플랫폼 게시, 공공 배포는 원저작자인 학생 및 법정대리인의 별도 동의를 받아 진행한다.

보완 방법:

- 보호자 동의서를 두 종류로 나눈다.
  - 필수: 수업 참여, 학습 기록 저장, 연구 분석용 비식별 활용
  - 선택: 작품 공개, 사진/영상 활용, 대회·에듀넷 공개자료 포함
- 동의하지 않은 학생은 보고서와 발표자료에서 완전히 비식별 처리한다.
- 학생 작품 공개 기본값은 `비공개` 또는 `학급 공개`로 둔다.
- 공개 서재는 교사 승인 후 공개되도록 한다.
- 학생 이름 대신 번호 또는 별칭을 사용한다.

### 16.7 현재 가장 약한 부분 5: 소프트웨어 제출 패키징

계획서는 웹애플리케이션의 경우 서버 환경, 실행 방법, 운영에 필요한 환경을 보고서에 포함하도록 요구한다. 또한 USB 폴더 구조로 document, media, program, source를 권장한다.

현재 약점:

- Vercel/Supabase/OpenAI API 기반 웹앱은 심사장에서 USB만으로 완전 실행하기 어려울 수 있다.
- API 키와 Supabase 환경변수는 제출 파일에 넣을 수 없다.
- 심사위원이 안정적으로 시연할 수 있는 데모 환경과 계정 안내가 필요하다.

보완 방법:

- `program` 폴더에는 접속용 `index.html` 또는 실행 안내 페이지를 둔다.
- `source` 폴더에는 소스 코드 전체와 `.env.example`을 둔다.
- `document` 폴더에는 실행 매뉴얼, 주요 화면 캡처, 계정 안내, 장애 대응 절차를 둔다.
- Vercel 배포 URL과 데모 계정을 제공한다.
- Supabase 로컬 복원 방법 또는 데모 DB 백업 절차를 문서화한다.
- API 키는 제공하지 않고, 심사용 배포 서버에서만 작동하게 한다.
- 인터넷 장애 시를 대비해 주요 화면 캡처와 수업 흐름 영상 또는 PDF 매뉴얼을 준비한다.
- 1920x1080, Chrome, Edge, Safari에서 동작 확인 캡처를 남긴다.

### 16.8 현재 가장 약한 부분 6: 블라인드와 공개 검증

계획서에는 연구보고서 6부 중 5부에는 출품자 개인정보를 절대 기재하지 않고, 소프트웨어에도 출품자 정보가 표시되지 않아야 한다고 되어 있다. 또한 입상 예정작은 공개 검증 대상이 된다.

보완 방법:

- 출품용 빌드에서는 학교명, 교사명, 지역명을 앱 화면에서 제거한다.
- 데모 계정 이름도 학교와 교사 실명이 드러나지 않게 만든다.
- 책 제목과 프로젝트명은 남기되, 출품자 정보는 시작 화면에 넣지 않는다.
- 발표용 시연 계정과 실제 수업 계정을 분리한다.
- 학생 작품 예시는 번호, 별칭, 비식별 이미지로 처리한다.
