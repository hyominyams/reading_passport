## 4. 수업 과정의 3가지 보호 절차

### 4.1 하드코딩 기반 1차 필터

목표:

- 학생 입력이 API로 전달되기 전에 위험 표현을 1차로 걸러낸다.
- 한국어와 영어 모두 대응한다.
- 욕설, 비속어, 음란어, 혐오·차별, 개인정보, 실존 인물 공격, 자해·위험 행동 유도 표현을 포함한다.

구현 위치:

- `src/lib/safety/youth-protection.ts`
- 모든 관련 API에서 공통 모듈로 import

적용 대상 API:

- `/api/story/guide-chat`
- `/api/story/validate`
- `/api/story/generate-draft`
- `/api/story/generate-image`
- `/api/story/produce`
- 필요 시 `/api/chat/save`, `/api/chat/flag`, `/api/story/translate`, 질문 생성/검증 API에도 확장

필터 방식:

- 원문 검사
- 공백 제거 검사
- 특수문자 제거 검사
- 대소문자 통일
- 반복 글자 축약
- 숫자/기호 치환 일부 대응
- 한국어 우회 표현 일부 대응
- 영어 leetspeak 일부 대응

출력 결과:

- `safe`: 통과
- `rewrite`: 교육적 변형 필요
- `block`: 차단
- `flag`: 교사 확인 필요

주의:

- 하드코딩 필터는 완전하지 않다.
- "빈틈없이"라는 표현은 보고서에서 피하고, "1차 사전 필터링과 교사 모니터링을 결합한 다층 보호"라고 설명한다.

### 4.2 이미지 생성 전용 필터

이미지 생성은 텍스트 생성보다 리스크가 크므로 별도 규칙을 둔다.

즉시 차단할 것:

- 음란 표현 또는 성적 행위 묘사
- 미성년자 관련 성적 표현
- 실제 학생, 교사, 특정인을 대상으로 한 공격·모욕·폭력 묘사
- 피, 절단, 고문, 잔혹 장면 등 노골적 폭력
- 자해, 자살, 위험 행동을 구체적으로 보여주는 장면
- 혐오·차별 상징 또는 특정 집단 공격
- 유명 캐릭터, 연예인, 작가 스타일 등 저작권·초상권 리스크가 큰 요청

교육적 변형할 것:

- 이야기상 필요한 갈등
- 다툼, 위기, 실수, 위험 상황
- 슬픔, 두려움, 상처, 어려움
- 비난과 배척이 사과, 화해, 회복으로 이어지는 장면

변형 예시:

- 학생 입력: `친구를 때리는 장면`
- 생성용 변형: `친구 사이에 갈등이 생겨 한 아이가 놀라 뒤로 물러서고, 주변 친구들이 말리려는 그림책 장면`

- 학생 입력: `괴물이 사람을 잡아먹는다`
- 생성용 변형: `무서운 괴물이 마을 앞에 나타나 사람들이 놀라 대피하고, 주인공이 용기 있게 해결 방법을 찾는 장면`

- 학생 입력: `나쁜 아이를 죽인다`
- 처리: 고위험 표현으로 차단하고 학생에게 다른 해결 방법을 쓰도록 안내

### 4.3 프롬프트화 단계의 교육적 변형

학생이 쓴 내용은 그대로 이미지 생성 프롬프트가 되면 안 된다. 프롬프트 변환 단계에서 교육적 표현으로 바꿔야 한다.

원칙:

- 학생의 창작 의도와 이야기 흐름은 유지한다.
- 노골적이고 자극적인 표현은 비노골적 장면으로 바꾼다.
- 갈등 장면은 직접적인 가해 장면보다 감정, 표정, 거리감, 주변 반응, 해결의 실마리로 표현한다.
- 실존 인물 또는 특정 학생을 연상시키는 요소는 제거한다.
- 성적 표현과 개인정보는 변형하지 않고 차단한다.
- 폭력 표현은 맥락에 따라 `rewrite` 또는 `block`으로 나눈다.

프롬프트 변형 시스템 문구 예시:

> 학생의 장면 설명을 그림책 이미지 생성 프롬프트로 바꾸되, 초등학생 교육활동에 적합한 표현만 사용하세요. 이야기상 필요한 갈등, 위험, 위기 장면은 허용하되, 노골적 폭력, 선정성, 실제 인물 특정, 혐오·차별, 개인정보는 포함하지 마세요. 부적절한 장면은 직접 묘사하지 말고 감정, 거리감, 주변 반응, 문제 해결의 단서가 드러나는 안전한 장면으로 바꾸세요.

| 구분 | 보호 조치 | 앱 구현 | 증빙 |
| --- | --- | --- | --- |
| 외부 AI 직접 사용 방지 | 학생이 ChatGPT/Gemini 계정 사용 안 함 | 서버 API 호출 | 시스템 구조도 |
| 입력 사전 필터링 | 욕설·음란·개인정보 등 차단 | 공통 안전 필터 | 코드 캡처, 흐름도 |
| 이미지 생성 보호 | 부적절 장면 차단/변형 | 이미지 API 전 필터 | 변형 예시 |
| 개인정보 보호 | 프롬프트에 개인정보 미포함 | 입력 안내 및 필터 | 동의서, 정책 페이지 |
| 산출물 권리 보호 | 학생 저작권 인정 | 공개 동의 기반 게시 | 약관, 동의서 |
| 교사 모니터링 | 플래그 확인 | 교사 대시보드 | 화면 캡처 |

보고서 문구:

> 본 연구에서는 생성형 AI API를 활용하되, 학생이 외부 AI 서비스에 직접 접속하거나 계정을 생성하지 않도록 하였다. 학생 입력은 서버에서 욕설, 비속어, 음란 표현, 개인정보, 실존 인물 공격, 혐오·차별 표현 등을 사전 점검하며, 이미지 생성 단계에서는 학생의 창작 의도를 유지하되 교육활동에 적합하지 않은 표현을 안전한 장면으로 변형하거나 생성하지 않는다. 또한 학생 산출물의 저작권은 학생에게 있음을 명시하고, 교육활동 목적 외 공개·출판·2차적저작물 작성은 별도 동의 후 진행하도록 설계하였다.
